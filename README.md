# SchoolBell

Desktop-додаток на Java для автоматичного шкільного розкладу дзвінків.

## Інтерфейс

Програма повністю перероблена у темному стилі. Основне вікно має три вкладки зліва:

- **Головна** — наступний дзвінок, точний відлік до нього, велика кругла кнопка ручного дзвінка та кнопка пропуску наступного сигналу.
- **Таблиця** — додавання, редагування, видалення, дублювання і сортування уроків та окремих дзвінків.
- **Налаштування** — звуки, гучність, журнал, глобальне ввімкнення розкладу, автозапуск, високий пріоритет процесу та поведінка системного трея.

Весь інтерфейс, поля, кнопки, таблиці, діалоги та вікна програми виконані на темному фоні, текст — білий.

## Можливості

- час початку та кінця уроку у форматі `HH:mm`;
- окремі записи **«Дзвінок»** з одним часом, власними днями тижня та вибором аудіо **Початок / Кінець / Власне**;
- окремі дні тижня для кожного уроку;
- окреме увімкнення/вимкнення кожного рядка;
- глобальне увімкнення розкладу;
- окрема звукова доріжка для початку та кінця уроку;
- ручний дзвінок із головної сторінки;
- пропуск саме наступного запланованого дзвінка;
- регулювання гучності;
- тест звуків і примусова зупинка відтворення;
- автоматичне збереження розкладу та налаштувань;
- журнал подій;
- згортання в системний трей;
- автозапуск разом із Windows або Linux;
- режим високого пріоритету: у Windows процес переводиться в `High`, а потік планувальника Java — у максимальний пріоритет;
- **Емітація активності / запобігання сну**: Windows через JNA + `SetThreadExecutionState`, Linux через `ProcessBuilder` + системний inhibitor;
- захист від повторного запуску одного й того самого дзвінка в межах однієї хвилини;
- необов’язкові попередження про повітряну тривогу/відбій для вибраної області та району через **NEPTUN** або **alerts.in.ua**;
- взаємовиключний вибір сервісу: можна ввімкнути NEPTUN, alerts.in.ua або вимкнути обидва повторним натисканням активної галочки;
- API токен alerts.in.ua не зберігається у `schedule.properties`.

> Використовується `High`, а не `Realtime`: Realtime може забрати процесорний час у системних процесів Windows і спричинити зависання ОС.

## Повітряні тривоги — NEPTUN / alerts.in.ua

Починаючи з **1.4.0**, у `Налаштуваннях` доступні два взаємовиключні джерела попереджень:

- **NEPTUN** — працює без API токена;
- **alerts.in.ua** — використовує персональний API токен.

Обидві галочки поводяться як перемикачі: одночасно може бути активна тільки одна. Повторне натискання активної галочки повністю вимикає попередження.

Вибір **області**, **району**, аудіо **Тривога** та **Відбій** завжди видимі незалежно від того, який сервіс зараз увімкнений. При виборі `alerts.in.ua` додатково з’являється поле API токена.

Токен alerts.in.ua зберігається окремо від звичайних налаштувань:

- у Windows програма спочатку намагається записати користувацьку змінну середовища `SCHOOLBELL_ALERTS_IN_UA_TOKEN`;
- якщо Windows не дозволяє це зробити, використовується резервний файл `alerts-in-ua.token` у каталозі поруч із `SchoolBell.exe`;
- токен ніколи не записується в `%APPDATA%\SchoolBell\schedule.properties` і не друкується у журналі програми.

Для alerts.in.ua SchoolBell використовує `GET https://api.alerts.in.ua/v1/alerts/active.json` з HTTP заголовком `Authorization: Bearer <token>`. Перевірка виконується раз на 6 секунд, тобто не перевищує задокументований hard limit 12 запитів за хвилину з однієї IP-адреси. Обробляються саме записи `alert_type=air_raid`.

Якщо вибрана конкретна область і район, тривога вважається активною при повітряній тривозі в цьому районі/громаді або при загальнообласній тривозі. Для `Уся область` достатньо активної повітряної тривоги в будь-якій частині вибраної області.

При переході зі стану «немає тривоги» у «тривога» програється вибраний трек **Тривога**, а при переході назад — **Відбій**. Якщо SchoolBell запускається, коли вибрана територія вже під тривогою, сигнал тривоги програється один раз.

> SchoolBell використовує зовнішні інформаційні сервіси і не замінює офіційні сигнали оповіщення.

## Аудіо

Починаючи з **1.2.1**, для MP3/M4A/AAC/FLAC/WMA та інших стиснених форматів у Windows першим використовується **Windows Media Foundation через WPF MediaPlayer**. Програма чекає подію `MediaOpened` або `MediaFailed`, тому більше не вважає файл успішно запущеним лише тому, що MCI повернув код `0`. Це виправляє випадок, коли журнал писав «запуск», але фактично була тиша.

Для WAV лишається надійний нативний MCI/SoundPlayer шлях, для MIDI — MCI. Після Media Foundation доступні резервні Windows Media Player COM, MCI та Java Sound. У виборі файлу доступні WAV/WAVE, MP3, FLAC, OGG/OGA, OPUS, M4A, AAC, WMA, AIFF/AIF, AU та MIDI/MID. Для рідкісних кодеків реальна підтримка все ще залежить від декодерів, установлених у Windows.

У Linux SchoolBell спочатку використовує зовнішні системні аудіобекенди (`ffplay`, `mpv`, `gst-play-1.0`, `cvlc`), а Java Sound залишається резервом.

## Вимоги

Java 17 або новіша.

Перевірка:

```bash
java -version
javac -version
```

## Windows

Готовий Windows x64 файл знаходиться тут:

```text
dist\SchoolBell.exe
```

`SchoolBell.exe` містить актуальний JAR усередині та при першому запуску розпаковує його у `%LOCALAPPDATA%\SchoolBell\app`. Для запуску потрібна Java 17 або новіша; лаунчер автоматично шукає Java в `JAVA_HOME`, `PATH`, типових каталогах JDK/JRE та реєстрі Windows.

Звичайна JAR-збірка на Windows:

```bat
build.bat
```

Запуск JAR без консольного вікна:

```bat
run.bat
```

## Linux

JAR:

```bash
chmod +x build.sh run.sh
./build.sh
./run.sh
```

Windows x64 EXE можна крос-компілювати прямо з Linux, якщо встановлений Go:

```bash
chmod +x build-exe-linux.sh
./build-exe-linux.sh
```

Результат: `dist/SchoolBell.exe`.

## Де зберігаються налаштування

Windows:

```text
%APPDATA%\SchoolBell\schedule.properties
```

Linux:

```text
~/.config/SchoolBell/schedule.properties
```

## Автозапуск

На Windows SchoolBell створює запис користувача в:

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
```

На Linux створюється:

```text
~/.config/autostart/schoolbell.desktop
```

Якщо програма запущена через `SchoolBell.exe`, запис автозапуску вказує безпосередньо на `SchoolBell.exe`. Якщо запущена через JAR — запис містить команду `javaw -jar ...`.


## 1.5.1 — Блокування сну та вимкнення дисплея

У **Налаштування → Робота програми** додано два взаємовиключні методи, щоб ноутбук не переходив у сон і не пропускав заплановані дзвінки:

- **JNA / SetThreadExecutionState (Windows)** — викликає `kernel32!SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED)`. Windows не повинна автоматично переводити систему в сон або вимикати дисплей. Вимкнення опції або завершення SchoolBell скидає execution state назад до `ES_CONTINUOUS`.
- **ProcessBuilder / системні утиліти ОС (Linux)** — у KDE/Plasma спочатку використовує `kde-inhibit --power --screenSaver` (і, якщо доступний, додатково `systemd-inhibit`), щоб PowerDevil не гасив дисплей і система не засинала. Для GNOME використовується `gnome-session-inhibit`, загальний резерв — `systemd-inhibit`. Процес inhibitor завершується одразу після вимкнення опції або закриття SchoolBell.


### Виправлення 1.5.1

Версія 1.5.0 блокувала системний сон, але на Windows не ставила `ES_DISPLAY_REQUIRED`, а на KDE могла потрапити в загальний `systemd-inhibit`, який не на всіх конфігураціях блокує PowerDevil/DPMS. У 1.5.1 режим утримує також сам дисплей увімкненим.

Одночасно активний тільки один метод. Повторне натискання на активну галочку вимикає запобігання сну. Якщо вибрати Windows-метод у Linux або Linux-метод у Windows, програма покаже пояснення і не змінить активний режим.

Для Windows EXE лаунчер використовує **JNA 5.19.1**. Якщо бібліотеки ще немає у `%LOCALAPPDATA%\SchoolBell\app`, лаунчер один раз завантажує її з Maven Central, перевіряє SHA-256 і кешує. Якщо мережа недоступна, SchoolBell все одно запускається, але Windows-метод JNA буде недоступний до появи бібліотеки.

Для запуску JAR у Windows рекомендується `run.bat`: він так само підтягує JNA у локальну папку `lib`. У Linux JNA для запобігання сну не потрібна.

## 1.4.1 — Linux audio backend

На Linux SchoolBell більше не покладається лише на Java Sound для MP3/M4A/FLAC/OGG/OPUS.
Порядок відтворення: `ffplay` -> `mpv` -> `gst-play-1.0` -> `cvlc` -> Java Sound.
На Arch/CachyOS рекомендовано встановити `ffmpeg` (`sudo pacman -S ffmpeg`) або `mpv`.
Кнопка «Зупинити звук» завершує і зовнішній Linux-плеєр.
